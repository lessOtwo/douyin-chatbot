# 当前实施计划

日期：2026-10-21。当前架构是**私信适配 → 业务服务保存消息 → FastGPT 工作流 → 业务服务发送**。FastGPT 管可视化话术与分支；业务服务管账号隔离、去重、暂停/恢复、发送状态、待处理问题和线索候选。产品需求与验收口径见 [PRD](PRD.md)。

1. **行业与入驻**：行业下维护多个项目及各自问句；商家凭一次性邀请在页面选行业，把本行业项目分入主做／其他可做／不做，并填写纯数字抖音号、抖音昵称等门店资料；平台审核时必须选择有权读取且已发布的 FastGPT 工作流，核验平台调用密钥后，以数字抖音号生成账号并同时关联工作流。旧行业问句与旧商家版本保留在数据库供历史核对，不参与新入驻。
   审核退回须填写原因，并生成 6 小时修改链接；管理员复制发送，商家可带入原资料修改后提交新版本。管理端可删除已撤销邀请和未被引用的行业／项目；账号接入移除会停止新消息，历史会话保留。
2. **工作流接入**：把已审核商家资料、项目分组、问句及可取得的客户昵称传入对应 FastGPT 应用；模糊需求先选择项目，明确项目才用对应问句。同行分支固定回复且不留资；线索仅区分电话／微信，后续联系偏好可更正。继续完善首次索取、兜底次数和拒绝状态；验证 `chatId` 恢复、重试、长会话和双端历史。项目变量与审核绑定工作流已接入代码；FastGPT 已有发布版本，其实际内容仍需验收。
   当前实验分支已发布“客服小妹”语气：一次生成的长回复由业务服务拆为两条依次发送，按生成轮次累计至 50 后自动暂停，后续消息留待处理。该行为已做定向模拟和工作流场景检查，真实抖音私信仍待渠道接通。
3. **商家线索**：运营后台按抖音号、昵称、门店名筛选电话／微信候选，按导出状态筛选、多选导出三列 XLSX，并生成七天有效的会话记录链接。后续仍需按商家授权展示线索并记录线下跟进状态；没有在线人工座席。
4. **真实渠道**：取得甲方私信接口契约后实现验签、发送窗口、回执和小流量验收。现阶段模拟发送不代表真实送达。

部署入口：Windows `start.ps1`，Linux `start.sh`；业务后台 `http://localhost:8088`，FastGPT `http://localhost:3000`。启动与更新保持持久卷，不清理数据库卷。平台工作流调用密钥由管理员统一配置，商家无需填写；本地首次配置可在 FastGPT 启动后运行 `python tools/provision_fastgpt_app_key.py`，再重启业务服务。当前尚无已审核的实际商家账号，真实渠道也未接通。
