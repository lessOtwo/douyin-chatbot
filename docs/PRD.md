# 抖音私信 AI 客服 PRD

版本：v0.9｜2026-10-22｜实施中

![业务流程图](business-flow.png)

## 目标

商家私信由业务服务接收、保存并交给 FastGPT 工作流处理。机器人简要回应咨询，主动邀请客户自愿留下电话或微信，再由商家线下联系。客户拒绝后最多再尝试一次；明确要求停止联系时立即停止。当前没有在线人工座席，无法回答的问题进入业务后台列表。

## 1. 行业与入驻

平台维护**行业 → 项目 → 项目开场问句**，草稿与发布版分离；行业不配置问句。例：装修装饰下的“老房翻新” → “您想做局部改造还是整屋翻新？”项目可分别保存、发布，商家只能选择本行业已发布项目。

平台发有有效期、令牌校验且只能提交一次的邀请链接；有效期可选 6、12、24 小时，默认 6 小时。商家直接在页面选择行业，再把该行业项目分别归入“主做／其他可做／不做”，各组可多选，同一项目只能处于一组，至少选一项主做。随后填写纯数字门店抖音号、抖音昵称、完整店名、服务区域、营业时间、门店详细地址（选填）、联系电话及是否可公开、实际可提供的资料或服务、入驻联系人；页面预览后提交审核。提交时服务端重新校验令牌、项目归属与分组。审核通过前，新版本不替换已发布资料。不收集项目价格或方案表。审核员必须从有权读取且已发布的 FastGPT 工作流中选择一项，服务端再次核验工作流及平台调用密钥后，才可审核通过；首次通过时，以门店抖音号生成账号，并在同一事务中关联商家与所选工作流。抖音昵称只用于展示。后续版本若更换抖音号，须先处理账号迁移，不能静默修改已有账号 ID。

已撤销的邀请可删除记录；行业及项目可删除，但被商家版本或有效接入账号使用时应拒绝。账号接入可移除，停止接收该账号的新消息，保留历史会话和发送记录；有待处理或待核对消息时先处理再移除。

审核退回必须填写原因。系统保存退回原因并生成 6 小时有效的新修改链接；管理员复制原因和链接，自行发给商家，不自动发送短信或微信。商家打开新链接后看到退回原因和上次填写的资料，可修改、预览并再次提交为新版本；原邀请链接仍不可重复使用。链接过期后管理员可重新生成。向外部商家发送时需使用商家可访问的业务后台地址，不能发送本机 `localhost` 链接。

门店资料只作为可确认事实。机器人不讨论具体价格、报价区间或方案细节；客户追问时说明需由门店根据实际需求确认，并说明留下联系方式后由哪家门店、为何联系。不得虚构资料、报价、服务或联系结果。

## 2. 对话与留资

业务服务保存原始消息和会话；每轮给 FastGPT 发送**本轮一条客户消息**、当前已审核商家资料及其项目分组／项目问句，使用同一活动会话的非空 `chatId` 保持历史。暂停后恢复使用新 `chatId` 代际；超时或发送取消时先核对状态，不盲目重试旧代际。平台统一配置工作流调用密钥，商家无需配置；审核时绑定已发布工作流。真实渠道授权仍待验收。

客服采用亲切、轻快的“客服小妹”语气，简短口语化回复；价格、联系方式和拒绝等场景仍需直接清楚。FastGPT 每轮只生成一次；业务服务将超过 50 字的回复优先按标点拆成两条、依次发送，并在会话记录中展示两条。每个会话最多自动生成 50 轮回复，拆成两条仍计一轮。第 50 轮回复发送后自动暂停；后续客户消息保留待处理，不再调用模型，后台显示已达上限且不可恢复机器人。

FastGPT 先识别客户项目：新会话没有明确需求时，业务服务将商家全部主做项目和其他可做项目组成一条选择问句，主做项目排前，并允许客户直接描述其他需求；识别到主做或其他可做项目后，仅在关键信息不明时使用**该项目**问句一次。客户已说明需求就跳过重复提问；询问不做项目时如实说明。简短回应后主动邀请留下电话或微信，无须机械等待多轮。客户问商家联系方式时，可请客户留下自己的联系方式，由商家主动联系。首次索取后客户拒绝或长期未回复，可再索取一次，兜底话术为“我这个是商家号，线上发联系方式出去会封号，您的联系方式方便留一下吗？我让门店加您。”第二次拒绝后不再索取；明确停止要求立即生效。沉默后的主动消息取决于甲方接口能力。

客户本轮主动留下本人电话或微信时，机器人固定回复“收到，稍后店长联系您详聊。”，不再索要其他信息。模型判断客户希望使用的联系渠道：手机号默认归电话；客户说“不要打电话”或“加我微信”时，归微信。线索列表只显示“电话／微信”两类；客户后续更正联系偏好时，更新该会话已有线索类型。联系方式只从客户本人消息原文提取为**线索候选**，保留来源；候选不等于已验证、已发送给商家或已跟进。商家查看本商家线索并在线下联系后回填状态，这部分仍待开发。

运营后台按抖音号、抖音昵称或门店名称模糊搜索线索，并按是否已导出筛选；当前筛选结果支持多选、全选和单行导出。导出生成仅含“类型、联系字段、会话记录链接”三列的 XLSX，成功生成后记录导出时间。会话记录链接由随机令牌保护，有效期七天，仅展示创建链接时已有的客户消息和已发送回复；管理员可单独生成链接并复制。正式环境需把业务后台公开地址配置为商家可访问的地址，不能使用 `localhost` 链接。导出状态不等于号码有效或商家已完成跟进。

工作流结合客户昵称和消息识别同一或相关行业商家。明确为同行时仅回复“不用呢 谢谢”，不索取或保存线索；该会话后续消息沿用同行状态。不确定身份时继续按普通客户处理。渠道适配在能取得昵称时传入昵称，未取得时依据消息判断。

## 3. 验收与实施边界

| 关键场景 | 验收标准 |
| --- | --- |
| 行业与入驻 | 项目问句分草稿／发布；邀请页按行业多选且分组互斥；跨行业项目被拒；令牌过期或用过即失效；审核须选有权限且已发布的工作流，工作流或平台调用密钥不可用时保持待审核 |
| 开场与答疑 | 模糊需求按主做在前列出全部可做项目；明确项目用对应问句；已知需求不重问；不输出具体报价或方案 |
| 留资节奏 | 主动首次邀请；拒绝/沉默后最多一次兜底；停止要求立即生效 |
| 同行识别 | 明确为同一或相关行业商家时，只回复“不用呢 谢谢”；无新线索，后续仍沿用同行回复 |
| 线索导出 | 搜索与已导出筛选准确；多选／全选导出 XLSX 三列；逐行可生成会话链接；链接过期后不可查看历史 |
| 会话一致性 | 只发本轮消息；恢复换 `chatId`；重试、长会话及业务库/FastGPT 历史可核对 |
| 回复样式与上限 | 客服小妹语气；长回复一次生成、最多两条顺序发送；同会话第 50 次生成后暂停，第 51 条客户消息不再触发生成 |
| 真实私信 | 拿到甲方接口契约后再实现授权、回调、发送与回执，模拟发送不算上线验收 |

当前 FastGPT 工作流已有发布版本，仍需核验发布内容与项目场景；商家审核时完成应用绑定。留资状态、商家线索页与真实渠道仍需继续实施。
